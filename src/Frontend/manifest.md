# Манифест кодстайла проекта

Документ описывает единые правила именования и стилизации, обязательные к соблюдению всеми участниками проекта.

---

## 1. Именование CSS-классов по методологии БЭМ (схема Гарри Робертса)

Используется классическая схема **Block-Element-Modifier** в варианте Гарри Робертса, где:

- Блок (**Block**) — независимый компонент интерфейса.
- Элемент (**Element**) — часть блока, не имеющая самостоятельного значения вне блока. Отделяется от блока двумя подчёркиваниями `__`.
- Модификатор (**Modifier**) — вариация блока или элемента (внешний вид, состояние, поведение). Отделяется двумя дефисами `--`.

### Синтаксис

```
.block {}
.block__element {}
.block--modifier {}
.block__element--modifier {}
```

### Примеры

```css
.card {}
.card__title {}
.card__image {}
.card--highlighted {}
.card__title--large {}
```

### Правила

- Названия блоков, элементов и модификаторов пишутся в **kebab-case** (через дефис), например `.search-form`, `.search-form__input`.
- Модификатор с булевым значением записывается как `--modifier-name` (например, `--disabled`).
- Модификатор с ключ-значением записывается как `--key_value` (например, `--theme_dark`), либо через дефис `--theme-dark` — выбранный вариант фиксируется единым по всему проекту.
- Вложенность БЭМ не должна превышать один уровень: `.block__element__element` — недопустимо. Вместо этого элемент рассматривается относительно ближайшего блока: `.block__sub-element`.
- Не допускается использование классов тегов (`div.block`) или ID-селекторов для стилизации.

## 2. Именование папок

- Все имена папок пишутся в **PascalCase** (с заглавной буквы каждого слова, без разделителей).

### Примеры

```
Components/
Pages/
UserProfile/
ShoppingCart/
```

### Запрещено

```
components/
user-profile/
user_profile/
```

---

## 3. Именование файлов

### 3.1. TSX-файлы

- Файлы с расширением `.tsx` именуются в **PascalCase** (верблюжья нотация с заглавной первой буквы), так как каждый такой файл, как правило, экспортирует React-компонент, имя которого совпадает с именем файла.

**Примеры:**

```
Button.tsx
UserCard.tsx
ShoppingCartItem.tsx
```

### 3.2. Остальные файлы

- Все остальные файлы (`.ts`, `.css`, `.json`, `.utils.ts`, тестовые файлы и т.д.) именуются в **camelCase** (верблюжья нотация со строчной первой буквы).

**Примеры:**

```
useUserData.ts
formatDate.ts
apiClient.ts
constants.ts
button.module.css
```

### Сводная таблица

| Тип сущности          | Нотация                          | Пример                  |
|------------------------|-----------------------------------|--------------------------|
| Папка                  | PascalCase                       | `UserProfile/`           |
| Файл `.tsx`            | PascalCase                       | `UserCard.tsx`           |
| Остальные файлы        | camelCase                        | `formatDate.ts`          |
| CSS-класс              | kebab-case (БЭМ)                 | `.user-card__title`      |

## 4. Модульная стилизация (CSS Modules)

- Стили компонентов подключаются исключительно через **CSS Modules** (`*.module.css` / `*.module.scss`).
- Каждый компонент имеет собственный файл стилей, лежащий рядом с компонентом в той же папке.
- Глобальные стили (сбросы, переменные, шрифты) выносятся в отдельные файлы и не смешиваются с модульными стилями компонентов.
- Импорт стилей осуществляется как объекта классов:

```tsx
import s from './userCard.module.css';

export const UserCard = () => {
  return (
    <div className={s['user-card']}>
      <h3 className={s['user-card__title']}>Заголовок</h3>
    </div>
  );
};
```

- Объект стилей всегда импортируется под коротким алиасом **`s`** (а не `styles`) — это единое соглашение по всему проекту.

- Внутри модульного CSS-файла имена классов по-прежнему следуют методологии БЭМ (см. раздел 1) — модульность решает проблему изоляции стилей на уровне сборки, но не отменяет договорённости об именовании классов.
- Использование глобальных селекторов внутри модуля (`:global(...)`) допускается только в исключительных случаях и должно быть обосновано в комментарии рядом с кодом.

### Структура компонента (пример)

```
Components/
  UserCard/
    UserCard.tsx
    userCard.module.css
    useUserCardData.ts
```

Файл `index.ts` в папках компонентов **не используется** — импорт компонента осуществляется напрямую по его пути, например:

```tsx
import { UserCard } from 'Components/UserCard/UserCard';
```

## 5. Медиафайлы и ассеты

- **Иконки** — только формат **`.svg`**.
- **Изображения** (фотографии, иллюстрации, баннеры и т.п.) — только формат **`.webp`**.
- Имена файлов ассетов пишутся в **camelCase**, как и остальные файлы проекта (см. раздел 3.2).

### Примеры

```
Assets/
  Icons/
    arrowRight.svg
    userAvatar.svg
    closeIcon.svg
  Images/
    heroBanner.webp
    profilePlaceholder.webp
```

### Правила

- Растровые изображения, приходящие в других форматах (`.jpg`, `.png`, `.jpeg`), перед добавлением в проект конвертируются в `.webp`.
- Если изображению требуется несколько разрешений (retina, адаптив), суффикс размера добавляется через `@`, без изменения регистра имени: `heroBanner@2x.webp`.
- Для иконок, требующих нескольких цветовых вариаций, вариант указывается суффиксом: `closeIconWhite.svg`, `closeIconDark.svg`.

---

## 6. Итоговые правила проекта

1. CSS-классы — БЭМ (схема Гарри Робертса), kebab-case.
2. Папки — PascalCase.
3. Файлы `.tsx` — PascalCase.
4. Все прочие файлы — camelCase.
5. Стилизация — только через CSS Modules, с БЭМ-именованием классов внутри модулей; объект стилей импортируется под алиасом `s`.
6. Папки компонентов не содержат `index.ts` — импорт производится напрямую из файла компонента.
7. Иконки — `.svg`, изображения — `.webp`; имена ассетов — camelCase.
